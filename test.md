## Аутентификация и авторизация. Непрозрачные и прозрачные токены.
-  Аутентификация — проверка подлинности пользователя путём сравнения введённого им пароля (для указанного логина) с паролем, сохранённым в базе данных пользовательских логинов.

- Авторизация (англ. authorization «разрешение; уполномочивание») — предоставление определённому лицу или группе лиц прав на выполнение определённых действий

- Токен - это структура данных, используемая для подтверждения личности и/или права пользователя.

## Объектная модель документа (DOM)

- DOM (Document Object Model) — программный интерфейс, представляющий HTML-документ как дерево объектов.
- Каждый HTML-элемент представлен узлом дерева (тег, текст, атрибуты и т.д.).
- С DOM можно взаимодействовать через JavaScript (`document.getElementById()`, `querySelector()`).
- Позволяет динамически изменять страницу: структуру, содержимое, стили.
- Часто обновление DOM — дорогая операция по производительности.

## Виртуальная объектная модель документа (Virtual DOM)

- Virtual DOM — легковесная копия реального DOM, используемая React.
- React сначала обновляет Virtual DOM, а затем сравнивает его с предыдущей версией.
- Изменения (патчи) применяются только к изменённым участкам реального DOM.
- Это повышает производительность по сравнению с прямыми манипуляциями DOM.

## Время жизни компонентов React

- Этапы жизненного цикла:
  - **Mounting** — создание и вставка в DOM.
  - **Updating** — обновление при изменении `props` или `state`.
  - **Unmounting** — удаление из DOM.
- Используются хуки, например `useEffect` с различными зависимостями для управления этими этапами.

## JSX

- JSX — расширение синтаксиса JavaScript, позволяющее писать HTML-подобный код внутри JavaScript.
- Используется внутри React-компонентов для описания интерфейса.
- JSX преобразуется в `React.createElement(...)`.
- Поддерживает встраивание JavaScript-выражений через `{}`.

## Связь компонентов

- **Props** — механизм передачи данных от родителя к дочернему компоненту.
- **Callbacks** — функции, передаваемые вниз для обратной связи (например, обработка событий).
- Для глобальной связи используются Context API или Redux.

## Потоки данных в компонентах React

- Поток данных в React односторонний: сверху вниз (от родителя к потомку).
- Изменение состояния происходит через `setState` или `useState`, и компоненты перерисовываются.
- Для изменения данных в родителе используется подъём состояния (callback в props).

## Состояние компонентов в React

- Локальное состояние управляется через хук `useState`.
- Состояние влияет на отображение компонента.
- Обновление состояния инициирует повторный рендер компонента.

## Хуки времени жизни компонентов React

- Основной хук — `useEffect`:
  - Без зависимостей: выполняется при монтировании.
  - С зависимостями: при изменении конкретных значений.
  - С функцией очистки: при размонтировании.
- Аналоги классовых методов `componentDidMount`, `componentDidUpdate`, `componentWillUnmount`.

## Работа с формами в React встроенными инструментами

- Используются контролируемые компоненты (`input`, `textarea`, `select`).
- Значение поля хранится в `state`, обновляется через `onChange`.
- Требует ручной валидации, обработки ошибок и управления состоянием.

## Работа с формами в React при помощи библиотеки Formik

- Упрощает управление формами: состояния, валидация, обработка.
- Предоставляет API и компоненты для управления формой.
- Поддерживает интеграцию с Yup для декларативной валидации.

## Маршрутизация в React

- Используется библиотека `react-router-dom`.
- Основные компоненты:
  - `<BrowserRouter>` — корневой компонент.
  - `<Routes>` и `<Route>` — описывают маршруты.
  - `<Link>` и `useNavigate` — навигация.
- Позволяет создавать SPA с несколькими страницами.

## Архитектура Redux приложения

- Центральное хранилище (`store`) управляет состоянием всего приложения.
- Состояние изменяется только через `actions`, обрабатываемые `reducers`.
- Архитектура упрощает управление сложными состояниями и отладку.

## Действия, диспетчеризация в Redux

- `Action` — простой объект `{ type: 'TYPE', payload: data }`.
- `dispatch(action)` — отправка действия в Redux store.
- `reducer` — функция, которая обновляет состояние в зависимости от типа действия.

## Middleware и асинхронные операции в Redux

- Middleware — функция, перехватывающая `dispatch` для расширения поведения.
- Для асинхронных действий используется `redux-thunk` или `redux-saga`.
- Позволяет выполнять API-запросы внутри `dispatch`.

## Создание пользовательских middleware в Redux

- Middleware имеет следующую форму:
  ```js
  const logger = store => next => action => {
    console.log('dispatch', action);
    return next(action);
  };
- Добавляется через applyMiddleware() при создании хранилища.

## Принципы SOLID

- **S** — Single Responsibility Principle: один класс = одна ответственность.
- **O** — Open/Closed Principle: открыто для расширения, закрыто для изменений.
- **L** — Liskov Substitution Principle: подклассы могут заменять базовые классы.
- **I** — Interface Segregation Principle: интерфейсы должны быть узкими и специфичными.
- **D** — Dependency Inversion Principle: зависимости строятся на абстракциях, не реализациях.

## Порождающие паттерны проектирования

- **Singleton** — один экземпляр на всё приложение.
- **Factory Method** — создание объектов через общий интерфейс.
- **Abstract Factory** — создание связанных объектов без указания конкретных классов.
- **Builder** — пошаговая сборка объекта.
- **Prototype** — клонирование существующих объектов.

## Структурные паттерны проектирования

- **Adapter** — преобразует интерфейс одного класса в интерфейс другого.
- **Bridge** — разделяет абстракцию и реализацию.
- **Composite** — иерархия объектов с единым интерфейсом.
- **Decorator** — динамически добавляет новое поведение.
- **Facade** — единый интерфейс к подсистеме.
- **Flyweight** — разделение состояния между объектами.
- **Proxy** — объект-заместитель с дополнительным поведением.

## Поведенческие паттерны проектирования

- **Observer** — оповещение подписчиков об изменениях.
- **Strategy** — выбор алгоритма во время выполнения.
- **Command** — инкапсуляция запроса как объекта.
- **Mediator** — централизует взаимодействие объектов.
- **State** — поведение объекта зависит от его состояния.
- **Chain of Responsibility** — цепочка обработчиков.

## Слоистая архитектура ПО

- Модель с разделением на уровни:
  - UI (презентация)
  - Бизнес-логика (service)
  - Доступ к данным (repository)
- Каждый слой отвечает за свою зону ответственности.
- Облегчает тестирование и поддержку.

## Протокол HTTP

- Клиент-серверный протокол передачи данных.
- Методы:
  - `GET`, `POST`, `PUT`, `DELETE`, `PATCH` и др.
- Коды ответа:
  - 2xx — успех, 4xx — ошибка клиента, 5xx — ошибка сервера.
- Используется в веб-приложениях и API.

## Схема URL

- Формат: `scheme://host:port/path?query#fragment`
- Пример: `https://example.com:443/api/users?id=1#section`
- Части:
  - `scheme` — протокол (`https`)
  - `host` — домен
  - `port` — порт (по умолчанию 80/443)
  - `path` — путь к ресурсу
  - `query` — параметры
  - `fragment` — якорь

## Инъекция зависимостей

- Внедрение зависимостей в класс извне, а не создание внутри.
- Упрощает тестирование и расширение.
- В ASP.NET Core встроен DI-контейнер:
  - `AddSingleton`, `AddScoped`, `AddTransient`.

## Архитектура ASP.NET Core

- Основана на middleware-пайплайне.
- Основные файлы:
  - `Program.cs`, `Startup.cs` (в старых версиях).
- Регистрация сервисов в `IServiceCollection`.
- Использует контроллеры или минимальные API.

## Последовательность обработки HTTP-запроса в ASP.NET Core

1. Запрос поступает в middleware.
2. Обрабатывается каждым middleware по цепочке.
3. Доходит до endpoint (контроллер/обработчик).
4. Ответ возвращается обратно через те же middleware.

## Конфигурации приложения в ASP.NET Core

- Источники конфигурации:
  - `appsettings.json`, `environment variables`, `user secrets`, `command line`.
- Доступ через `IConfiguration`.
- Настройка параметров через `Options Pattern` (`IOptions<T>`).

## Обработка запросов в ASP.NET Core. Приём данных из различных частей HTTP-запроса. Ответ на HTTP-запрос

- Получение данных:
  - `[FromQuery]`, `[FromBody]`, `[FromRoute]`, `[FromForm]`
- Ответы:
  - `Ok()`, `BadRequest()`, `NotFound()`, `Created()`, `StatusCode(...)`

## ORM Entity Framework Core

- ORM для .NET с поддержкой LINQ.
- Основные сущности:
  - `DbContext` — единица работы.
  - `DbSet<TEntity>` — таблицы.
- Поддерживает миграции, отслеживание изменений, ленивую и жадную загрузку.

## Миграции базы данных

- Механизм управления изменениями схемы БД.
- Команды:
  - `Add-Migration <name>`
  - `Update-Database`
  - `Remove-Migration`
- Позволяют версионировать и применять изменения схемы.
